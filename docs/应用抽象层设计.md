**结论：所谓"前置"只剩端口落地这一件，而且它是机械活——这是上一版计划书最大的判断错误。**

上一版把"契约设计"和"前置改造"混在一起，都压给作者，还写了"代码只由作者实现"。结果是你花一天搬完类、加完 id，卡在 `SwingImp` 上——那本来就不该你写。本版把两件事拆开。

## 二、分工（本版的核心改动）

| 谁 | 做什么 | 产物 |
|---|---|---|
| **你** | 定契约（签名与语义）、拍 §三 的默认值、每次收货跑一条命令 | `go` / `no-go` |
| **AI** | 其余全部代码：端口收尾、Main 改造、事件总线、App 实现、测试、HTTP/JS | 可编译的 diff |

四条边界，交给 AI 时原样附上：

1. 不得改 `core/interfaces`、`core/records`、`core/events` 的公开签名。要改，先写一句话申请（P0 是唯一一次例外）。
2. 一次只做一个施工包，只动包里"只动"列出的文件；不夹带重构、不顺手改名。
3. 提交前必须：`mvn -q -DskipTests compile` 通过，现有测试全绿。
4. 不改 `backend` 的领域语义（agent loop、provider、tool 执行方式）。

为什么这样分：**接口错在语义，迁移错在编译。** 前者只有你能判断，后者编译器能判断。混在一起，就会出现"写着难受、还不全"。

## 三、已定语义（不用再讨论）

上一版留了 13 条待定决策，这是"写不下去"的第二个原因。本版直接给默认值，想改哪条说一声。

| # | 项 | 已定 | 改成别的会怎样 |
|---|---|---|---|
| 1 | 序号 | 全局单调 `seq`，单写者，环形缓冲 4096；落后即发 `GapDetected` | 每会话独立 seq 要前端合并两个序，首版不值 |
| 2 | 快照 | `snapshot()` 的会话列表与 `seq` 在同一把锁内取 | 否则前端拼不出自洽状态 |
| 3 | 忙时 `submit` | 拒绝并发 `UserMessageRejected`；插件 `inject` 走"并入当轮" | 排队要额外做队列和位置 UI |
| 4 | 消息 id | 会话内唯一；`fork` 复制同 id 合法（渲染 key 用 `sessionId + messageId`） | 全局唯一就要给 fork 重新发号 |
| 5 | 会话状态 | `SessionStatus` 是链级：首轮 `RoundStarted` 起，`RoundFinished(chainEnded)` / `RoundFailed` / `RoundCancelled` 止 | 按轮推导会在轮间闪 `IDLE` |
| 6 | 工具状态 | 两个维度并存：工具消息 `MessageState` 恒 `CONFIRMED`，生命周期只看 `ToolState` | 两维真值表前端维护不了 |
| 7 | `regenerate` | 截断重跑，没有"作废"态 | 保留作废要回答"进不进上下文" |
| 8 | 审批 | 推送 `HostRequestOpened` + `pending()` 补拿；超时 10 分钟 → `Reject` + `CloseReason.TIMEOUT` | 只有拉取口就得轮询 |
| 9 | 通知 | `Notice` 事件；端口期 `sink.notify` 与它同源 | 两个来源会重复弹 |
| 10 | 配置变更 | `ConfigChanged` 不带新值，前端收到重拉 | 带值要定义每种 key 的载荷 |
| 11 | 长会话 | 首版全量返回；单个工具结果 > 32KB 截断并置 `truncated` | 分页要另定游标协议 |
| 12 | 默认 effort / mode | 核心配置；`SessionView.effort/mode` 给**生效值** | 给原始值，前端要自己回落，会与输入区显示不一致 |
| 13 | 空会话 | 显式命令：`createSession(ws, reuseIfEmptySessionId)`、`deleteSessionIfEmpty(id)`；core 不持有 `activeId` | 隐式 active 在多前端下无解 |
| 14 | 线程 | sink 实现内部切 EDT；事件在单分发线程回调，监听器不得阻塞 | 各调用点自己切，必漏 |

## 四、施工包

每包可单独交给一个 AI 会话。"只动"是白名单，超了打回。

### P0 端口收尾与契约冻结（小，纯新增）

**目标**：`frontend.tmp` 转正，契约冻结。

- `frontend/tmp/{AgentSink, AiWriter, ToolWriter}` → `core/sink/`
- 三处形参统一为**已落库的 `Message`**：`AiWriter appendAi(String sessionId, Message message)`、`ToolWriter appendToolCall(String sessionId, Message message)`、`void appendUser(String sessionId, Message message)`。语义：**core 先写库，sink 只渲染这条记录**。端口是内部接缝，用仓库实体；对外契约仍然是 `MessageView`。
- 补两个写句柄的线程约定注释（"实现方负责切 EDT"）。

**只动**：这 3 个文件 + 引用它们的 `SwingImp`。
**验收**：`mvn -q -DskipTests compile`。
**你**：看 `AgentSink` 的 9 行签名，说"冻结"。

### P1 端口落地（大，行为不变）

**目标**：`Main` 不再认识 `Window`；状态写入归 core，Window 只负责画。

顺序（第 1–3 步一次提交：只加不改；第 4–5 步一次提交：替换与删除）：

1. **新增**：`Window` 加三个 render-only 入口——`showUserMessage(Message)`、`openAiCard(Message)`、`openToolCard(Message)`，只画卡不落库（与 `insertMessageCard` 同一个入参，不用转换）；旧方法原样保留。
2. **新增**：`SwingSink implements AgentSink`（纯委托 + 内部 `invokeLater`）、`SwingApp`（组合根：`new Window`、注册 4 个入站回调）、`AgentCore`（把 `Main` 里的链与状态逻辑抽出来，字段 `ConversationRepository repo` + `AgentSink sink`；`Main` 只留启动与插件静态入口）。
3. **收口用户消息的写入**：新增 `AgentCore.submit(sessionId, clientMsgId, text)`——先 `repo.appendMessage` 拿到 `Message`，交给 `sink.appendUser` 渲染，最后起链；`Window.submitInput` 不再 `addUserMessage`，只把文本交给 `SwingApp` 接的这一条路径。
4. **替换**：`Main` 里 23 处 `window.` → `sink.`/`repo.`；24 处 `SwingUtilities.` 按性质拆三类——纯渲染（通知、生成态、流式增量、工具卡、审批）移进 sink；状态写（`appendUiMessages`、`whenBackgroundTaskDone`、`updateUsageInfo`）交给 core；启动与取快照（`main`、`apiEnsureSession`/`apiInject`、`snapshotMessagesOnEdt`）归组合根，**前提是仓库已加锁（见 §六）**；`Window.AiStream` / `Window.ToolCallHandle` 的 16 处签名 → `AiWriter` / `ToolWriter`。
5. **删除**：`SwingImp`；`apiEnsureSession` / `apiInject` 改为 `AgentCore` 实例方法，`Main` 保留静态 holder 供插件回调。

**不改**：`backend`、`core/*` 的签名、Window 的布局与渲染逻辑。
**验收**：编译 + 现有测试全绿 + §七 手工清单 6 条。
**你**：启动一次，按清单点 6 下。

### P2 事件总线（中）

**目标**：状态变更可被外部订阅。

- 新增 `core/events/EventBus`：`long publish(...)`（seq 由 bus 发）、`AutoCloseable subscribe(sinceSeq, listener)`、环形 4096、缺口发 `GapDetected`、单分发线程。
- `AgentCore` 在每个状态变更点 `publish`，**与 sink 并存**。Swing 此时仍走 sink、不订阅，避免双渲染。
- 新增 `EventBusTest`：seq 单调、从 `sinceSeq` 重放、缺口、监听器抛异常不影响分发。

**只动**：`core/events/EventBus.java`（新）、`AgentCore`、`core/events/EventBusTest.java`（新）、`core/events/GapDetected.java`（只改注释）。
**验收**：`mvn -q -Dtest=EventBusTest test`。
**你**：无。

### P3 CoreApp（大）

**目标**：`AgentApp` 有实现，第二个前端能只依赖接口。

- `core/app/CoreApp.java implements AgentApp`：`snapshot` / `session` / `sessionsSince`、9 个命令、`pending` / `answer` / `cancel`（`requestId → CompletableFuture` 注册表）、`RuntimeConfig`、`Notice`。
- `core/app/EnumMapping.java`：`spi.enums.AgentMode` ↔ `core.enums.AgentMode`、`spi.enums.ReasoningEffortEnum` ↔ `core.enums.ReasoningEffort`（两套枚举现在并存，投影必须映射）。
- 命令落到 `ConversationRepository`：`createSession` 用显式 `reuseIfEmptySessionId`，`deleteSessionIfEmpty` 直接判 `isKnownEmpty`——都不碰 `activeId`。

**只动**：`core/app/*`（新）、`AgentCore`（暴露命令入口）。
**验收**：`CoreAppTest`——建会话、submit 落库、快照含消息、置顶排序、`deleteSessionIfEmpty` 幂等。
**你**：看 `CoreAppTest` 的 5 个断言名，确认语义没跑偏。

### P4 无头冒烟（中）

**目标**：不启动 UI 能跑完一轮，且能进 `mvn test`。

- `AgentCore` 构造注入 `Supplier<Provider>`（默认 `ProviderFactory::createResponseProvider`），测试可换假 Provider。
- `HeadlessSmokeTest`：临时仓库 + 假 Provider（3 个 delta + poison）→ `submit` → 断言事件序列 `RoundStarted → MessageAppended → MessageDelta×3 → MessageCompleted → RoundFinished(chainEnded=true)`。
- `Main` 加 `--headless`：stdout 逐行打印事件。

**只动**：`AgentCore` 构造、`HeadlessSmokeTest`（新）、`Main` 的参数分支。
**验收**：`mvn -q -Dtest=HeadlessSmokeTest test`；`java -jar ... --headless` 能对话一轮。
**你**：跑一次 `--headless`，看输出。

### P5 HTTP / JS（中）

**目标**：第二个真实前端。

- `core/http/*`：`GET /snapshot`、`GET /session/{id}`、`POST /submit`、`GET /events?since=`（SSE）、`POST /answer`。
- 一个最小页面：输入框 + 消息列表 + 审批按钮。
- JSON 用已有的 `JsonKit`（Jackson 已引入）。

**只动**：`core/http/*`（新）、`web/`（新）。
**验收**：浏览器发一条消息看到流式；`curl /snapshot` 有 `seq`。
**你**：打开页面发一句话。

| # | 位置 | 现象 | 正确做法 |
|---|---|---|---|
| 1 | `:110` | `setGenerating` 恒传 `false` | 透传 `generating` |

## 六、结构性问题（P1 / P3 顺手处理）

| 问题 | 现状 | 处理 |
|---|---|---|
| 双枚举 | `core.enums.AgentMode` / `ReasoningEffort` 与 `spi.enums.AgentMode` / `ReasoningEffortEnum` 并存；`Conversation` 仍返回 spi 类型 | P3 加 `EnumMapping`，只在投影边界转换 |
| `activeId` 壳 | `ConversationStore` 仍持有 `activeId`，`newConversation` / `switchTo` / `remove` 还在用它 | 留给 Swing；core 侧走 §三-13 的显式命令 |
| `AppSettings` 整包在 core | 916 行里仍含 `uiTheme`、`window*` 等 UI 偏好 | 首版接受，挂账（§八） |
| `fork` 复制 `messageId` | `Conversation.fork` 用 `Message.copy()`，id 原样带过去 | 符合 §三-4，在 `fork` 上补一行注释即可 |
| `Window.addUserMessage` 按 active 落库 | `:920-925` | P1 后不再被 sink 使用 |
| 旧章节引用 | `core/events/GapDetected.java:5` 写着"见设计文档 8.2"，本版已无 §8 | P2 顺手改成"见施工计划 §三-1"（只改注释） |
| 仓库线程安全 | `ConversationRepository` 的 `conversations` / `messages` 是裸 `ArrayList`，只有 `getOrCreate` / `save` 带 `synchronized`；写入迁出 EDT 后，HTTP 读与 core 写会撞 | P1 给读写加同一把锁（或读侧 `CopyOnWriteArrayList`）；P3 的 `CoreAppTest` 补一个"写的同时快照"的用例 |

## 七、验收

| 命令 | 期望 |
|---|---|
| `mvn -q -DskipTests compile` | 无输出、退出码 0 |
| `mvn -q test` | 现有测试全绿（含 `WindowGuiTest`、`PersistenceTest`、`LazyLoadTest`） |
| `mvn -q -Dtest=HeadlessSmokeTest test` | P4 后：一轮事件序列齐全 |
| `java -jar ... --headless` | P4 后：stdout 有 `RoundStarted` … `RoundFinished` |

P1 之后的人工清单（6 条，逐条点）：

1. 新建会话 → 发消息 → 流式出字
2. 切走再切回，消息还在
3. 工具调用：参数增量、执行态、终态结果
4. 停止按钮：已生成部分保留
5. 后台 bash 完成：卡片翻转 + 自动续一轮
6. 审批卡：允许 / 拒绝都生效

## 八、挂账（明确不做）

- **配置面 CRUD**：方案增删改、MCP 名单写入。`RuntimeConfig` 首版只读 + `setEnabledTools` / `setToolProperty` / 默认 effort·mode。
- **长会话分页**：首版全量 + 工具结果 32KB 截断。
- **`AppSettings` 三类拆分**：UI 偏好继续留在 core，等第二个前端稳定后再拆。
- **Swing 改纯订阅者**：P1 之后 Swing 仍走 sink 渲染，只是状态写入归 core。真订阅化收益低、改动大，不做。
- **插件 API 迁移**：`apiEnsureSession` / `apiInject` 继续留在 `Main` 的静态入口，内部转 `AgentCore`。
