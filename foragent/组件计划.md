### P0-4 权限确认卡 `[x]`

**为什么**：工具目前全是只读类，一旦接入写文件/执行命令，"模型说要改就改了"没有拦截点。
后端 `AgentMode`（PLAN/EDIT/FULL_ACCESS）已建好并从输入区取值，但执行侧还没有消费它。
**实际做法**（机制与策略分离）：
1. **后端只提供机制**：`Tool#readOnly()`（default false——认错方向代价不对称，宁可多问一次），
   `ToolRead`/`BAD_TOOL`/`EMPTY_TOOL` 覆写 true（占位工具 `name()` 为 null、execute 无副作用，
   为它们弹确认是噪音）；`PromptParams` 加 `agentMode` + `approvalGate`（getter 里 agentMode
   为 null 按 EDIT 处理，漏接线只会多问，不会不问就执行）；新建 `ToolApprovalGate`
   （`@FunctionalInterface boolean allow(ToolCall, AgentMode)` + 常量 `DENIED_RESULT`）；
   `OpenAiProvider` 把两者透传进 `getVisitor`，钩子放在**线程池任务开头**——
   `putIntoBQ(FunctionToolCallDoneEvent)` 照旧先发（卡片先出来才有地方挂按钮），
   未放行则 `setResult(DENIED_RESULT)` + `INCOMPLETE` 直接 return，工具一行不执行；
   阻塞只发生在池线程，SSE 读流线程绝不停顿。
2. **策略在调用方**：`AgentMode#requiresApproval(tool)`——FULL_ACCESS 直通、EDIT 只拦非只读、
   PLAN 全拦（`tool==null` 按最严）。`Main` 在建 params 时（EDT 上）快照 `getSelectedMode()`
   传进本轮请求；钩子实现 `invokeAndWait` 让卡片翻"待确认"，然后 200ms 一轮轮询 future，
   每轮先看 `cancelled`——用户点停止不会把等待的池线程吊死，也不占 EDT。
3. **卡片是工具卡的第四态**，不新造角色也不新增事件类型（原计划的 BaseEvent 审批事件没要——
   审批发生在 provider 池线程上，走句柄直接送达，单队列反而绕）：
   `ToolCallHandle#requestApproval(future)` → `MessageCard.approval` 挂 future
   （挂卡片不挂按钮，`drainCard` 不清——待确认卡滚出视口再滚回来还要重画按钮），
   `buildToolContent` 判 `running && approval != null && !isDone()` 出"待确认"
   （新增 `Ui.WARNING`：浅 0xB45F06 / 深 0xD29922，Theme 同步）+ "允许/拒绝"两按钮
   （`Ui.primaryButton`/`Ui.dangerButton`）。点击只写 future 不碰执行，然后 `rebuildCard`
   （`finish` 里的 drain/fill/fit/贴底跟随抽成公用）重画回"运行中…"。卡片已终态还请求审批
   → 立即 `complete(false)`，不让等待方悬着。
**已知边界**：待确认是纯显示态不落库（崩了重启按 P0-5 的"运行中"残留看）；等待期间关窗
不拦截（关窗走 `System.exit`，池线程随进程消失）。
Shot：APPROVAL_OK（待确认徽标+两按钮在视图树 → 点"允许"写 future 且回"运行中…" →
