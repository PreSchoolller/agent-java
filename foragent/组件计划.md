## 待做

### P0-1 AI 输出渲染 Markdown 与代码高亮 `[ ]`

**现状**：AI 回复是纯文本（JTextPane），`**加粗**`、代码块都按字面显示。
**做法建议**：在 `Window.insertMessageCard` 的 content 构建处替换成 Markdown 渲染器。
两条路线：
1. 零依赖自写轻量解析（标题/粗体/行内代码/代码块/列表），用 StyledDocument 的
   属性段落渲染，复杂度可控但覆盖面有限；
2. 引入 flexmark-java 解析成事件流，再映射到 StyledDocument（要多一个 maven 依赖）。
代码块建议整体渲染成等宽字体 + 浅灰圆角底 + 右上角"复制"。
**涉及**：`gui/Window.insertMessageCard`、新增 `gui/MarkdownRenderer`。

### P0-2 流式输出体验 `[~]`

**现状**：`addMessageCard` 返回 JTextPane，后端可以反复 setText 实现流式，但没有
打字机动画、没有光标、停止后已生成部分的处理全靠后端自觉。
**做法建议**：加工具方法 `appendAiChunk(JTextPane, String)`（追加 + 光标标记 +
自动滚底仅当本来就在底部）；停止时前端不 clear 内容，由后端决定。
**涉及**：`gui/Window`、后端接入文档同步更新。

### P0-3 重新生成 `[ ]`

**现状**：无。Agent 应用高频操作。
**做法建议**：最后一张 AI 卡片底部加"重新生成"按钮（复用复制按钮的排版位置），
点击后回调 `onRegenerate(Consumer<Conversation>)`，由后端删除旧回答并重新请求。
**涉及**：`gui/Window`（卡片尾行 + 回调字段）、`store/ConversationStore`（删尾条消息的方法）。

### P1-1 单条消息删除/撤回 `[ ]`

**做法建议**：卡片右上角悬停显示"…"菜单（删除），会话模型加 `removeMessage`，
删除后按当前会话重建瀑布流即可。

### P1-2 搜索关键词高亮 + 会话排序/置顶 `[ ]`

**现状**：搜索只过滤列表，不高亮命中词；列表按最近使用排序，无法手动置顶。
**做法建议**：渲染器里对命中片段加 `<mark>` 样式（现有 HTML 渲染器已支持）；
会话加 `pinned` 字段，排序时置顶优先（`ConversationStore` 持久化字段顺带加版本号）。

### P1-3 多模型 profile `[ ]`

**现状**：`AppSettings` 只有一套配置。
**做法建议**：设置面板加"配置方案"下拉，`AppSettings` 存 `Map<String, Profile>` +
当前方案名；后端按 profile 请求。涉及 `store/AppSettings`、`gui/SettingsDialog`。

### P2-1 深色主题 `[ ]`

**做法建议**：所有颜色已经集中在 `gui/Ui`，抽象成 `Theme` 接口（light/dark 两套常量），
设置面板加主题切换，切换后 `showConversation` 重建即可。工作量主要在逐个色值校对。

### P2-2 长会话性能 `[ ]`

**现状**：每条消息一张卡片，测量用克隆 JTextPane，几百条消息后切换会话会明显卡。
**做法建议**：测量结果按"文本指纹 + 宽度档位"缓存；列表超过阈值时只渲染视口附近
的卡片（简易窗口化），或迁移到 `JList` 虚拟化方案（改动大，先不动）。

### P2-3 托盘最小化 / 全局快捷键 `[ ]`

**做法建议**：`SystemTray` + `TrayIcon`，关闭按钮改为可配置最小化到托盘；
全局快捷键需要 JNA/JNI，权衡后大概率砍掉。

### P2-4 历史文件版本化 `[ ]`

**做法建议**：`history.json` 顶层加 `{"version":1, ...}`，`load` 按版本走迁移分支，
避免以后加字段时把用户旧历史读丢。
